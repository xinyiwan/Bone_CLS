# Lung Image Review Tool

This repository contains a Streamlit-based web application designed for the manual verification of thoracic CT scans previously flagged as **"Lung incomplete"**. It provides an interactive grid interface to visualize coronal snapshots, allowing the user to validate the automated decision or move valid cases back to the active project.

### Review Actions & Logic

The tool filters the input Excel for cases with `Reason: "Lung incomplete"` and presents them for review. The user can apply one of the following actions via the interface:

| Action | UI Element | Condition / Logic | Outcome |
| :--- | :--- | :--- | :--- |
| **Quarantine** | 🟥 | **True Positive.** The scan actually cuts the lung or is invalid. | **No Action.** The case remains in the Quarantine folder. Excel status updates to "Checked:Lung incomplete". |
| **Lung Complete** | 🟦 | **False Positive.** The scan covers the full lung volume, despite the automated flag. | **Move Folder.** The code moves the DICOM series from `path_quarantine` **back to** `path_project`. Excel status updates to "Moved". |
| **Review** | ⬛ | **Uncertain.** The case requires a deeper inspection . | **Flag.** No file movement. Excel status updates to "Review need". |

### Prerequisites

The application expects specific data structures generated by the Segmentation Pipeline:
1.  **Quarantine Data:** Folder with quarantine cases.
2.  **JPG Previews:** Coronal snapshots generated .
3.  **Images:** Folder with images with complete lung.
4.  **Excel Report:** The `Quarantine.xlsx` file containing the list of flagged cases.

All the folders have to follow the following structure:

```mermaid
 ro2_lc       <-- (This is the 'path_project')
    ├── Patient_001          <-- Level 1: PatientID
    │   ├── CT-Study_20230101   <-- Level 2: StudyID
    │   │   ├── Series_001   <-- Level 3: SeriesID (Contains .dcm files)
    │   │   └── Series_002
    │   └── CT_Study_20240505
    │   └── PT_Study_20240505
    ├── Patient_002
    └── ...

```
In Dockerfile check and update the port (8502 by default): 

```bash
EXPOSE 8502
HEALTHCHECK CMD curl --fail http://localhost:8502/_stcore/health || exit 1
CMD ["streamlit", "run", "main.py", "--server.port=8502", "--server.address=0.0.0.0"]
```

##  Docker Usage

###  Build the Image
Run this command in the Reviewer_tool directory to create docker image:

```bash
docker build -t reviewer_tool .
```
###  Run code

Run this command to launch the pipeline:

```bash
docker run --rm -p num_port:num_port  -v /path_project:/data  -v /path_config_folder:/Parameters_config   reviewer_tool
```
###  Docker Command Variables

| Variable / Flag | Type        | Description                                                                                                                                                                                                                                 |
| :--- |:------------|:--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **`docker run`** | **COMMAND** | The base instruction to initialize and start a new container instance.                                                                                                                                                                      |
| **`--rm`** | **FLAG**    | **Auto-Cleanup.** Automatically removes the container file system when the process exits. Prevents disk clutter.                                                                                                                            |
| **`-p num_port:num_port`** | **PORT**    | **Num Port** Port number to create interface. It need to be the same in Dockerfile.  .                                                                                                                                                      |
| **`-v /path_project:/data`** | **VOLUME**  | **Data Mapping.** Maps your local DICOM folder (Host) to `/data` (Container).<br> *You must replace `/path_project` with your real local path.*                                                                                             |
| **`-v /path_config_folder:/Parameters_config`** | **VOLUME**  | **Config Mapping.** Maps the folder containing your JSON file to `/Parameters_config` (Container).<br> **CRITICAL REQUIREMENT:** This folder **MUST** contain a file named `Parameters_config.json` with the valid configuration structure. |
| **`reviewer_tool`** | **IMAGE**   | **Target Image.** The identifier of the Docker image to execute (must match the tag used during the build step).                                                                                                                            |

##  Configuration (`Parameters_config.json`)

The pipeline behavior is controlled entirely by an external JSON configuration file. You do not need to modify the code to change paths or thresholds.

### Example `Parameters_config.json` structure:

```json
{
    "path_project": "/data/RO2/ro2_lc",
    "path_quarantine": "/data/RO2/ro2_lc_Quarantine",
    "path_jpg": "/data/RO2/ro2_lc_Coronal-Images",
    "output_excel_quarantine": "/data/Excels_resultados/Quarantine_ro2_lc.xlsx",
    
    "n_rows": 3, 
    "n_cols": 8 
}
```

###  Path Variables 

| Variable | Type          | Description                                                                                 |
| :--- |:--------------|:--------------------------------------------------------------------------------------------|
| **`path_project`** | **INPUT**     | The root directory containing the raw DICOM structure to be processed.                      |
| **`path_quarantine`** | **OUTPUT**    | Directory where discarded or defective series will be moved.                                |
| **`path_jpg`** | **OUTPUT**    | Directory where Coronal JPEG snapshots will be saved for visual QC.                         |
| **`output_excel_quarantine`** | **FILE PATH** | Full path for the Excel file that logs all quarantined cases and the reasons for rejection. |
| **`n_rows`** | **Number of rows**          | 3 rows by default for each batch                                                            |
| **`n_cols`** | **Number of columns**         | 8 columns by default for each batch                                                         |
